# Self-hosted relay deployment

Deploy the existing `infra/relay` stack into your own Cloudflare account with your own
identity provider and database. This is a deployment guide for the existing implementation,
not a fork: the only deployment-specific code is the database sizing config below.

Read [T3 Connect setup](./connect-setup.md) and the [relay README](../../infra/relay/README.md)
first; they own the Clerk and provisioning details.

## Prerequisites

- A Cloudflare account with a DNS zone you control, the **Workers Paid** plan (Queues,
  Hyperdrive and Durable Objects require it), and R2 enabled.
- A PlanetScale organization (Postgres). The retained production database defaults to the
  hosted relay sizing (`PS_160`, 2 replicas); a personal deployment shrinks it with
  `RELAY_DB_CLUSTER_SIZE` (for example `PS_5`) and `RELAY_DB_REPLICAS=0` (single node, non-HA).
- An Axiom organization (the stack always provisions tracing datasets and ingest tokens).
- Your own Clerk application. Create the `t3-relay` JWT template (`aud: t3-code-relay`) and
  the public CLI OAuth application exactly as in [T3 Connect setup](./connect-setup.md).
  A self-hosted IdP (Logto/Authentik) is out of scope: the Clerk SDK is integrated in the
  relay, web, server and mobile clients, so replacing it is a rebuild, not a deployment.

## Configuration lives outside the repository

Keep every credential and deployment value in an env file outside the checkout, for example
`~/.config/t3-relay-selfhost/relay.env`, and pass it with `--env-file`:

```sh
vp run --filter t3code-relay deploy -- --stage prod --env-file ~/.config/t3-relay-selfhost/relay.env
```

Required values (see `infra/relay/.env.example`):

```dotenv
RELAY_API_ZONE_NAME=example.com
RELAY_TUNNEL_ZONE_NAME=example.com   # may equal the API zone
CLERK_PUBLISHABLE_KEY=pk_test_...
CLERK_SECRET_KEY=sk_test_...
CLERK_JWT_AUDIENCE=t3-code-relay
APNS_ENABLED=false                   # no Apple push credentials needed
RELAY_DB_CLUSTER_SIZE=PS_5
RELAY_DB_REPLICAS=0
AXIOM_ORG_ID=...
```

Provider credentials resolve from Alchemy profiles (`~/.alchemy/credentials/`, OAuth with
automatic refresh) or from env: `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`,
`PLANETSCALE_API_TOKEN_ID` + `PLANETSCALE_API_TOKEN` (+ `PLANETSCALE_ORGANIZATION`),
`AXIOM_TOKEN`. The mint signing key pair is generated by the stack and stored as Worker
secrets; never write it to a file.

Set `T3CODE_RELAY_CLIENT_CONFIG_ENV` to a path outside the repository so the stack's
`PublishClientConfig` action does not write the deployed relay URL into the checkout's
root `.env`.

## Stage naming

Alchemy state is per Cloudflare account. Deploying `--stage prod` in your own account owns
your zones and database there; it never touches the upstream hosted relay, which lives in a
different account and state store. `prod` gives `relay.<RELAY_API_ZONE_NAME>`; any other
stage name gives `relay-<stage>.<zone>` but references the `prod` stage's resources, so
deploy `prod` first.

## Static web hosting

Build `apps/web` with the public values of your deployment (process env wins over repo env
files) and host `apps/web/dist` on any static host, for example Cloudflare Pages:

```sh
VITE_T3CODE_RELAY_URL=https://relay.example.com \
VITE_CLERK_PUBLISHABLE_KEY=pk_test_... \
VITE_CLERK_JWT_TEMPLATE=t3-relay \
VITE_CLERK_CLI_OAUTH_CLIENT_ID=<public OAuth client id> \
vp run --filter @t3tools/web build
wrangler pages deploy apps/web/dist --project-name <name>
```

## Linking devices

Per device, run the environment server with runtime overrides (no rebuild needed for the
bundled server; a source checkout reads the same variables):

```dotenv
T3CODE_RELAY_URL=https://relay.example.com
T3CODE_CLERK_PUBLISHABLE_KEY=pk_test_...
T3CODE_CLERK_JWT_TEMPLATE=t3-relay
T3CODE_CLERK_CLI_OAUTH_CLIENT_ID=<public OAuth client id>
```

Then `t3 connect link` (browser authorization; headless devices use the device grant or an
SSH-forwarded loopback port 34338) and start the server. `t3 connect status` reports the
relay URL and reachability. The managed tunnel needs `cloudflared` on PATH or
`T3CODE_CLOUDFLARED_PATH`.

## Rollback

One step per device: `t3 connect unlink`, then restart the server without the override
variables (default hosted configuration) and `t3 connect link` again. The hosted relay and
its defaults are untouched by this deployment; removing the overrides restores them.
